OVERVIEW
========

CRITICAL: Debee is an ORCHESTRATOR, not a database tool
- It contains ZERO SQL statements
- It executes YOUR SQL scripts in order using psql and pg_restore
- All database logic lives in external files you provide
- Debee is a conductor, not a musician

WHAT DEBEE IS
-------------
A cross-platform database migration orchestrator for PostgreSQL.
Three implementations: PowerShell (debee.ps1), Bash (debee.sh), Python (debee.py).
All three have identical functionality and interfaces.

WHAT DEBEE DOES
---------------
- Reads configuration from .env files
- Executes external SQL scripts in order
- Calls PostgreSQL tools (psql, pg_restore)
- Manages execution flow and error handling
- Runs database tests
- Generates database object documentation

WHAT DEBEE DOES NOT DO
----------------------
- Create databases directly
- Define table schemas
- Contain SQL statements
- Know your database structure

ARCHITECTURE
------------

┌─────────────────┐
│     debee.*      │  ← Orchestrator (ps1 / sh / py)
└────────┬────────┘
         │
         ├── Reads: debee.env
         ├── Calls: psql -f recreate_script.sql
         ├── Calls: pg_restore backup.dump
         ├── Calls: psql -f 001_init.sql
         ├── Calls: psql -f 002_tables.sql
         ├── Calls: psql -f 003_functions.sql
         └── Calls: psql -f post_update.sql

WHY THIS DESIGN
---------------
1. Separation of Concerns: Orchestration logic separate from database logic
2. Flexibility: You control all SQL — debee just runs it
3. Reusability: Same orchestrator works for any PostgreSQL project
4. Transparency: All database changes in SQL files you can review
5. Version Control: SQL files tracked separately from the tool

DEPENDENCIES
------------
- PostgreSQL client tools (psql, pg_restore)
- One of: PowerShell 5.1+, Bash 4.0+, or Python 3.6+
- Python 3.6+ (for extract-db-objects.py, standard library only)
- No external Python packages required
